# 情绪指标系统设计

日期：2026-11-01
状态：待评审

## 意图

机器人现在完全靠静态人设说话：系统提示由人格文本、助手称呼和主人称呼拼成，
每轮不变。但真实对话里，用户的语气和处境一直在变——反复做不成一件事、机器人
迟迟没理解、事情很急，或者生活里遇到了难处。这时继续用同样的语气回应，会显得
迟钝甚至添堵。

这套系统在后台给出一个情绪指标，让模型在回答时语气跟着用户状态走，并在合适的
时候表达关心。它默认关闭，界面上不展示，只作为开发者可选的调试信息存在。

## 目标

- 识别用户说话时的情绪（烦躁、焦急、低落）和叙述内容对用户的影响。
- 用这些信号计算并保存情绪值，随时间衰减。
- 按四个维度（敏感度、语气幅度、主动性、延续性）控制它影响提示词的力度。
- 私聊里对所有用户生效；群聊只调整整体语气，不点名、不公开关心。
- 关闭时零额外模型调用，提示词与现在完全一致。

## 非目标

- 不在界面上显示情绪仪表盘或曲线；开发者选项只输出到日志。
- 不在群聊里按发言人单独记情绪，也不在群里点名关心任何人。
- 不改变模型能力、权限、工具行为或路由选择。
- 不做情绪标签的持久化展示（例如在用户资料里写“此人焦虑”）。
- 不依赖聊天之外的任何数据源（邮件、日程、外部服务）。

## 反目标（技术上成立也算失败）

- 机器人变得过度殷勤、每轮都嘘寒问暖，盖过用户真正要问的事。
- 群聊里公开点出某人的情绪，或对不熟的人套近乎。
- 把玩笑、反讽、正常吐槽当成低落，导致明显误判。
- 保存或回放聊天原文；只能保存概括后的近况。
- 判定调用故障拖慢或打断主流程。

## 数值模型

三个独立作用域，互不覆盖：

| 数值 | 键 | 来源 | 表达位置 |
|---|---|---|---|
| 主人值 | `owner`（全局一个） | 主人在私聊、群聊和 WebUI 里的发言 | 私聊与 WebUI 回复时注入 |
| 其他用户值 | `user:<adapter>:<user_id>` | 该用户私聊里的发言 | 私聊回复时注入 |
| 群气氛值 | `group:<adapter>:<group_id>`（即该群的会话标识） | 群内整体发言 | 群内回复时注入 |

- 群聊里别人发言只更新群气氛值，不触碰主人值。
- 主人在群里的发言同时更新群气氛值和主人值。
- WebUI（`web:owner`）的对话只更新主人值，不产生群气氛值。
- 群气氛的影响只体现在群内回话的整体语气；主人相关的关心等回到私聊再表达。

每个值都是一个 0–1 的强度，外加几个派生字段（见“状态”）。

## 判定流程

判定异步执行：用户消息到达后启动一个后台任务，与本轮回复并行；结果从下一轮
开始生效。判定失败、超时或任务被取消都不影响当前回复。总开关关闭时不起任务。

### 1. 规则筛

本地规则先看当前消息、该会话最近几条用户消息，以及本轮的工具执行情况。命中任一类
才进入模型判定：

- 否定/纠正：不、不对、不是、又、还是、怎么还 等连续出现
- 催促/焦急：快点、赶紧、马上、急、还在吗 等
- 语气加重：多个感叹号、反复使用的语气词或脏话
- 重复：最近 3 条用户消息与新消息高度相似（按分词重合度判断）
- 失败：最近几轮（含上一轮）出现工具调用失败；判定异步执行，当轮的失败要到下一轮才可见
- 生活困难词：累、病、疼、失眠、加班、压力、考试、分手、家里 等
- 长篇第一人称叙述：超过阈值字数且包含个人经历

规则命中时记一个粗粒度强度（命中类别的加权和），作为后续模型判定失败时的兜底。

### 2. 模型判定

输入：当前消息 + 最近几条用户消息 + 规则命中的类别（不含群内其他人的原文）。
输出严格 JSON：

```json
{"affect": "frustrated|anxious|sad|calm", "intensity": 0.0, "impact": 0.0, "situation": "≤40字概括"}
```

- `intensity`：说话时的情绪强度。
- `impact`：叙述的事情本身对用户的影响程度（平静地讲一件很重的事，也可以很高）。
- `situation`：概括出的近况，不抄原话、不写敏感细节；没有就留空。

路由：判断只由 System One 决策模型（Jev）完成：`light` 路由，为空则用 `memory`
路由；`intensity`、`impact` 用 `noul`，`affect` 用 `choice`。决策模型不产出自由
文本，因此 `situation` 由 `light` 路由的文本模型在同一个后台任务里补一次小调用；
没有可用文本模型时 `situation` 留空，数值仍然有效。没有可用决策模型时只用规则值，
文本模型不参与数值判定。

失败处理：超时、非法 JSON、字段缺失都视为“本轮无判定”，不更新状态，只记 debug 日志。

### 3. 合并与衰减

- 合成信号：`raw = 0.65 * intensity + 0.35 * impact`。
- 敏感度决定生效门槛：`threshold = 0.85 - 0.7 * sensitivity`（敏感度 0 时 0.85，
  1 时 0.15）。`raw < threshold` 时不更新，只做衰减。
- 已有值先按延续性衰减，再与新信号融合：`value = clamp(0.6 * decayed + 0.4 * raw)`。
- 衰减半衰期：`H = 6 小时 × 2^(4.8 × persistence)`，即延续性 0 约 6 小时、1 约 7 天。
- `situation` 在新一次判定给出非空值且 `raw` 不低于当前值时替换；同时记录时间戳。
- 群气氛值用同一条路径，但只记录 `value` 与 `situation`，不做按人拆分。

## 状态

使用现有 `records` 表，kind 为 `emotion`，键见“数值模型”。每条记录：

```json
{"value": 0.0, "affect": "", "impact": 0.0, "situation": "", "updated": 0.0, "source": "judge|rules"}
```

- 只存派生值，不存消息原文或消息 ID。
- 衰减是惰性的：读取时按 `updated` 计算当前值，不必定时任务。
- 删除或关闭功能不清理历史记录；重新开启后自然过期。

## 提示注入

新增一个纯函数，按作用域生成提示片段，注入本轮用户消息的 `<context>` 块（记忆和
时间也在这里），系统提示保持逐轮不变，避免破坏提示缓存：

- 私聊：使用该用户的值和近况。
- 群聊：只使用群气氛值；片段里明确“不点名、不评论个人状态，只调整整体语气”。

语气幅度决定措辞档位：

| 语气幅度 | 注入内容 |
|---|---|
| < 0.2 | 仅在值 ≥ 0.6 时加一句“对方状态不好，语气收敛、少开玩笑” |
| 0.2–0.6 | 一句语气要求 + 允许一句简短的理解或确认 |
| > 0.6 | 上一档 + 允许一句真诚的关心；同时要求不跑题、不重复关心 |

其它约束写进片段：关心最多一句；不要每轮都说；不要猜测用户没说的隐私；群聊里
不得点名或评论某个人。

近况片段：`situation` 非空且值高于门槛时附上“此前提到：<situation>（<时间>）”，
由模型自行决定是否自然接上。

主动性：

- 主动性 < 0.8：只在回复里体现。
- 主动性 ≥ 0.8 且值高于高门槛、且距上次主动关心超过节流时间：允许发起一条主动
  关心消息。实现上走现有 proactive 事件通道，由 Proactive Loop 按人设撰写，遵守
  `quiet_start` / `quiet_end` 与 `throttle_seconds`。只对主人私聊发起，复用现有
  owner 通知通道；不新增对普通用户的主动发送能力。

## 配置

`Settings.emotion`（Pydantic，新增）：

| 字段 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `enabled` | `false` | — | 总开关 |
| `sensitivity` | `0.5` | 0–1 | 多小的信号算数 |
| `tone` | `0.5` | 0–1 | 语气变化幅度 |
| `initiative` | `0.3` | 0–1 | 回复里主动关心的程度；≥0.8 允许主动消息 |
| `persistence` | `0.5` | 0–1 | 衰减半衰期 |
| `developer` | `false` | — | 打开后把判定结果与当前值写入日志 |

WebUI：`web/src/config/schema.ts` 增加对应字段，`SettingsPage` 增加“情绪”分组。
页面不展示任何当前情绪值；`developer` 只影响日志。

## 关闭时的行为

总开关关闭：不做规则筛、不调模型、不读写状态、不注入任何文本。与当前版本逐字一致。

## 测试

- 规则：各类命中与不命中样例；英文/中文标点。
- 合成与衰减：门槛、融合、半衰期、惰性读取。
- 提示片段：三档语气、私聊/群聊差异、近况出现条件、最大值不刷屏。
- 关闭：用假 LLM 断言零调用、零写入、消息上下文不变。
- 异步：判定超时、抛错或任务取消都不改变状态，也不影响本轮回复；结果从下一轮读取。
- WebUI：`web:owner` 的对话只更新主人值。
- 判定失败：超时/坏 JSON/缺字段不改变状态。
- 作用域：群内他人发言只更新群值；主人群内发言同时更新群值与主人值；私聊只更新本人值。
- 配置校验：范围越界报错；旧配置缺字段时默认关闭。
- 现有 337 项测试保持通过。

## 实现位置（建议）

- 新模块 `src/shiritaibot/emotion/`：规则、判定、状态、提示拼装各自独立，暴露少量函数。
- `config/__init__.py`：`EmotionConfig` 与字段。
- `agent/__init__.py`：消息到达时启动判定后台任务；下一轮拼上下文时读取并注入；
  群聊传群作用域，WebUI 传主人作用域。
- `web/src/config/schema.ts`、`SettingsPage.tsx`：配置表单。
- 日志：`developer` 打开时输出一行结构化判定结果。

## 已确定的决策

由需求方确认：

- 判定异步执行，下一轮生效，不增加回复延迟。
- WebUI 对话计入主人值。
- 主动消息只发给主人。
- 情绪判断用 Jev（System One 决策模型）实现。

由实现者决定（评审时可推翻）：

- 主人值使用单一键 `owner`，不按适配器拆分；WebUI 与各适配器的 owner 共用。
- 取样点是 Bot 实际处理的会话轮次：全部私聊用户、群里被唤起/触发的消息和 WebUI；
  未进入轮次的群消息不参与群气氛，避免为每条群消息调用模型。
- 群聊判定只喂当前消息，不回看群内其他人的原文。
- 失败信号取最近几轮的轮次记录，不读取当轮尚未发生的工具结果。
- `situation` 由 `light` 路由的文本模型在后台任务里补一次调用；没有文本模型时留空。
- 提示片段写入用户消息的 `<context>` 块，不改系统提示，保持提示缓存稳定。
- 没有决策模型时只保留规则值。
- 主动关心的值门槛为 0.75，且 `initiative >= 0.8`。
