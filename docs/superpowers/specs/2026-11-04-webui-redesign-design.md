# WebUI 对话体验重构设计

日期：2026-11-04
状态：待评审

## 背景

当前 WebUI 是一个「控制台」：左侧 16 个页面，对话只是其中一页。实际使用中暴露三个问题：

1. **对话顺序看起来是乱的**。根因是 `ChatPage` 在会话历史下方又追加了一个「已投递」区块（`ChatPage.tsx` 的 `delivered`），把最近 3 条出站回复固定贴在时间线末尾。这些回复本身已经是历史里的 assistant 消息（`agent/__init__.py:696` 写入，随后 `deliver()` 投递），所以既重复、又永远出现在最后，与它属于哪一轮无关。
2. **工具调用太吵**。每个 Agent 步骤都会铺一条可展开的工具调用块，一次多步任务下来页面被工具噪音淹没。
3. **视觉粗糙**。按钮是浅灰底、低对比，主操作和次要操作区分不明显。

## 目标

- 对话按真实时间顺序呈现，上下文清晰可读。
- 工具调用默认折叠，需要时再展开。
- 新增「对话模式」，布局参照 DeepSeek Harness 网页端：左侧会话栏 + 中央对话 + 底部输入。
- 把现有所有页面收进「设置」入口，点击按钮打开。
- 交互元素（按钮、选中项、输入框）颜色更鲜明、状态更清楚。

## 非目标

- 不引入「工作区 = 项目目录」的概念，不改后端会话模型。
- 不扩大 WebUI 的发送能力：仍然只能向 `web:` 开头的会话发消息，QQ 会话只读。
- 不改 Agent 循环、工具执行、审批等后端行为。
- 不做消息虚拟滚动、不做多标签页、不做深色模式（现有代码也没有）。

## 已定决策（来自用户）

1. 会话栏母分类用现成维度：**本机 / QQ 私聊 / QQ 群聊 / 后台任务**，下面挂具体对话。
2. 现有页面全部收进「设置」入口。
3. 视觉风格参照 DSH。

## 设计

### 1. 对话顺序

- 删除 `ChatPage` 中的 `delivered` 区块及对应的 `replies` 查询。出站回复不再单独渲染。
- 时间线只由 `/api/history` 的 `seq` 顺序驱动，后端已经是升序返回（`store.history`）。
- 一次请求（一个 `turn`）在历史中可能包含：user → assistant(工具调用) → tool → assistant(工具调用) → tool → assistant(最终文本)。渲染时必须保持这个链式顺序，不能把工具结果提到前面或把最终回复提前。

### 2. 消息渲染

新的消息组件替换现有 `AgentTimeline` 的渲染部分（分组逻辑可保留改造）：

| 类型 | 呈现 |
|---|---|
| 用户消息 | 右对齐浅灰气泡（`--bubble-user`），圆角 12px，最大宽度 80%，上方小字显示发言人 |
| 助手正文 | 左对齐无气泡，全宽，正文允许 Markdown（复用现有 `Markdown` 组件），上方小字显示助手名 |
| 工具调用 | 默认折叠。**连续的一段**工具活动（assistant 带 `tool_calls` 的消息 + 紧随的 `tool` 结果，中间没有纯文本助手消息或用户消息打断）合并成一个折叠组，标题形如「🔧 6 次工具调用 · shell, read ×5」，右侧 chevron |
| 工具调用（展开） | 每行一个：工具名 + 状态标签（完成 / 失败 / 执行中）+ 可继续展开的「参数」「结果」 |
| 带文本的工具消息 | 该消息的正文渲染在折叠组之外，工具部分进入组内 |
| 失败 | 工具结果解析出 `error` 时该行标红；本轮 `turn` 记录为 `failed` 时，最后一条助手消息左侧加红色边框并标注「本轮失败」 |
| 运行中 | 对话底部显示三点脉动指示；有新的工具调用时自动滚动到底（仅当用户已在底部） |

用户消息的 `<context local_time=...>` 注入块继续截断不显示（沿用 `split("\n<context")[0]`）。

### 3. 对话模式

**入口**：控制台顶部操作区新增「对话模式」按钮（`MessageSquare` 图标）；对话模式右上角是齿轮「设置」按钮，点击回到控制台。模式保存在 `localStorage["shiritaibot-mode"]`，可选值 `console` / `chat`，默认 `console`。

**布局**（`chat` 模式）：

```
┌──────────────┬────────────────────────────────────┐
│ ShiritaiBot  │  会话标题                 [设置] ⚙ │
│ [+ 新对话]   │────────────────────────────────────│
│              │                                    │
│ 本机         │        消息列表（最大宽 760px）    │
│  · 默认对话  │                                    │
│  · 11-04 14:32│                                   │
│              │                                    │
│ QQ 私聊      │                                    │
│  · 2064438401│                                    │
│              │                                    │
│ QQ 群聊      │                                    │
│  · 群 820215017                                   │
│              │────────────────────────────────────│
│ 后台任务     │  [输入框…………………………] [停止] [发送]  │
│  · 08c31f…   │                                    │
└──────────────┴────────────────────────────────────┘
```

- 侧栏宽度 260px，可折叠（< 900px 时变成抽屉，顶部汉堡按钮打开）。
- 分组规则按会话 id 前缀：`web:` → 本机；`private:` → QQ 私聊；`group:` → QQ 群聊；`background:` → 后台任务。其他前缀归入「本机」。
- 组内按最近活动时间倒序；每项显示标题和相对时间。当前选中项有浅色底和左侧 3px 强调条。
- 会话标题规则：`web:owner` → 「默认对话」；`web:<毫秒时间戳>` → 「对话 MM-DD HH:mm」；`private:<适配器>:<QQ号>` → 「QQ <QQ号>」；`group:<适配器>:<群号>` → 「群 <群号>」；`background:proactive:<hash>` → 「后台任务 <hash 前 6 位>」。
- 分组标题显示数量，空分组隐藏。
- 「新对话」只在本机组创建 `web:<Date.now()>`，并自动选中。它只存在于客户端状态，第一条消息发出、服务端产生 session 记录之前刷新即消失；`web:owner` 无论有没有 session 记录都固定列出。
- 选中 QQ 或后台会话时，底部输入框替换为只读提示（沿用现有文案：「这里只发送 WebUI 会话」）。

**运行状态与排序**：`records("session")` 不返回时间戳，因此会话列表的时间与「运行中」都从 `/api/records/turn` 推导（该 kind 已在接口允许列表内），不改后端：

- 每个会话的最近活动时间 = 该会话 turn 记录的最新 `at`；组内按它倒序。
- 「运行中」= 该会话存在 `status === "running"` 的 turn 记录，用于显示脉动指示和禁用发送。
- 轮询间隔与现有对话历史一致（2.5 秒），`turn` 实时事件到达时立即失效重取。

**审批**：当前会话存在 `status === "pending"` 且 `reviewer !== "model"` 的审批时，卡片内联显示在消息列表末尾，可直接允许/拒绝；审批来源沿用现有 `ApprovalCard` 组件和 `resolveApproval` 接口。

### 4. 设置入口

- 对话模式的齿轮按钮把模式切回 `console`，并打开控制台的「设置」页（`page = "settings"`）。
- 控制台保持现有布局与全部页面不变，只是多了「对话模式」按钮。
- 控制台里的「对话」页保留（与对话模式共用消息组件），不做删除，避免破坏现有入口。

### 5. 视觉规范

新增/修改 `tokens.css` 中的颜色：

| token | 旧值 | 新值 | 用途 |
|---|---|---|---|
| `--accent` | `#2563eb` | `#4d6bfe` | 主色（DeepSeek 蓝） |
| `--accent-strong` | `#1d4ed8` | `#3b5bfd` | hover / 按下 |
| `--accent-soft` | `#eaf2ff` | `#eef2ff` | 选中底、浅色按钮 |
| `--focus` | `#3b82f6` | `#4d6bfe` | 焦点环 |
| `--success` | `#15803d` | `#16a34a` | 成功 |
| `--danger` | `#b91c1c` | `#dc2626` | 危险 |
| 新增 `--bubble-user` | — | `#f1f3f7` | 用户气泡背景 |
| 新增 `--sidebar-active` | — | `#eef2ff` | 侧栏选中底 |

按钮规则：

- **主按钮（.primary）**：实心 `--accent`，白字，`hover` 用 `--accent-strong`，`active` 再深一档，`disabled` 用 40% 透明度且不改颜色。
- **次按钮**：白底 + `--border-strong` 描边，hover 变 `--accent-soft` 且文字变 `--accent`。
- 所有按钮统一高度 34px、圆角 8px、`transition: background 120ms, border-color 120ms`。
- 输入框 / 下拉框：hover 边框变 `--border-strong`，focus 时 2px `--accent` 边框 + 3px 焦点环。
- 链接风格的可点击文字用 `--accent`，hover 加下划线。
- 图标按钮 hover 显示 `--accent-soft` 圆形底。

### 6. 数据与状态

- 会话列表：`client.records("session")` 提供会话本身（每 10 秒刷新，沿用现有），`client.records("turn")` 提供最近活动时间与运行状态。
- 当前会话历史：`client.history(session)`，每 2.5 秒刷新；实时事件 `turn` / `reply` 时立即失效重取（已有 `useRealtime`）。
- 切换会话时显示骨架/加载态，避免闪出上一个会话的消息。
- 空态：没有任何消息时显示一句引导 + 模型未配置时指向设置。

## 验收标准

1. 一次包含多步工具调用的对话，消息顺序与发生顺序一致；页面上不再出现「已投递」重复块。
2. 工具调用默认不展开，一次 6 次调用的任务在页面上只占 1 行折叠组。
3. 点击「对话模式」进入 DSH 风格布局，「设置」能回到控制台且所有页面可访问；刷新后模式保持。
4. 会话栏按四个分组正确归类、按时间排序、可切换；新对话落在本机组。
5. 主按钮、选中项、焦点态颜色鲜明且与旧界面有肉眼可见的区别。
6. 对话模式在 1440px 与 390px 宽度下都不出现横向滚动；窄屏时侧栏可打开/关闭。控制台页面不在此次响应式范围内。
7. 当前会话有待审批时，对话里能看到审批卡片并直接处理。
8. 待审批的会话在侧栏有可辨认标记。

## 留给实现的判断

- 是否给消息加时间戳（默认不加，只在悬停时显示）。
- 工具调用折叠组是否需要「全部展开」快捷键（默认不做）。
- 是否把「后台任务」分组默认收起（默认展开，但只在有内容时显示）。
