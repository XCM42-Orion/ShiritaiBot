# Skill Creator

技能（Skill）是一份可安装的「操作手册」：把某类任务的流程、领域知识和可复用资源打包起来，
让你在遇到对应任务时按手册稳定地完成。本技能指导你用 skill_* 工具创建和维护技能。

## 技能是什么

```
my-skill/
├── SKILL.md          必需：YAML frontmatter + Markdown 说明
├── references/       可选：按需读取的参考资料（API 文档、规范、示例）
├── scripts/          可选：可通过 shell 执行的脚本
└── assets/           可选：模板、样例文件等输出素材
```

- **frontmatter** 只有 `name` 和 `description` 必填。`description` 是触发依据：系统提示里只展示
  名称和描述，你据此决定是否读取 SKILL.md。所以描述要同时写清「做什么」和「什么时候用」。
- **正文** 只在技能被触发后读取，写执行步骤和要点。
- **附带文件** 只在正文指引下用 `skill_read` 按需读取（渐进式披露），不要把所有内容塞进 SKILL.md。

格式细节见 `references/format.md`。

## 可用工具

| 工具 | 用途 |
| --- | --- |
| `skill_list` | 查看已安装技能，避免重名或重复造轮子 |
| `skill_read` | 读取技能的 SKILL.md 或其中的文件 |
| `skill_write` | 新建技能（SKILL.md 全文 + 可选附带文件） |
| `skill_update` | 修改单个文件：整体替换、精确片段替换或删除 |
| `skill_pack` | 打包为 `<name>.skill`，可再用 `qq_file_send` 发出 |
| `skill_install` | 安装主人发来的 .skill 文件（先 `qq_file_download`） |

## 创建流程

### 1. 弄清用途

先用具体例子确认技能要解决的问题，不要凭空设计。必要时向主人确认：

- 这个技能在什么场景下被用到？主人会怎么说（触发语）？
- 期望的产出是什么？有没有成功或失败的样例？
- 涉及哪些工具、外部服务或文件格式？

一次只问最关键的一两个问题。信息足够时直接动手。

### 2. 规划内容

对每个使用场景想一想：如果每次都从零开始做，哪些东西会反复重写或反复查询？

- 反复编写的同一段代码 → `scripts/` 下的脚本
- 每次都要查的规范、表结构、接口说明 → `references/` 下的文档
- 输出要用到的模板 → `assets/`

先用 `skill_list` 检查是否已有相近技能；有的话优先改进它。

### 3. 编写

用 `skill_write` 一次写入 SKILL.md 和附带文件。名称用小写字母、数字和短横线，例如
`weekly-report`。写作原则：

- **简洁**：你本来就是能干的模型，只写你不知道的东西——流程、约束、领域细节、坑点。
  每一段都问自己：去掉它会不会做错？
- **祈使句**：「先读取……再……」，而不是「本技能会……」。
- **自由度匹配风险**：容易出错、必须一致的步骤写死（或给脚本）；需要判断的部分给原则和例子。
- **SKILL.md 控制在约 500 行以内**；超出就拆到 `references/`，并在正文写明何时读哪个文件。
- **不写**：README、更新日志、安装说明等与执行无关的文件。
- 脚本要在说明中写清调用方式。技能目录路径由 `skill_read` 返回的 `directory` 给出，
  通过 `shell` 执行（会受工具权限约束）。

### 4. 验证与迭代

写完后用 `skill_read` 通读一遍，检查：

- frontmatter 的 `description` 是否足以让未来的你在正确场景触发它？
- 步骤是否可以照着执行，引用的文件是否都存在？

之后在真实任务中使用它。发现遗漏或误导时，用 `skill_update` 的 `old_text` / `new_text`
做精确修改，避免整体重写。

### 5. 打包分享（可选）

主人想把技能分享给别人时，用 `skill_pack` 生成 `.skill` 文件，再用 `qq_file_send` 发送。

## 安装别人发来的技能

1. 主人发来文件后，用 `qq_file_download` 下载得到本地路径。
2. 用 `skill_install` 安装；同名技能已存在时先问主人是否覆盖，再设置 `replace=true`。
3. 安装后用 `skill_read` 浏览其 SKILL.md，向主人简要说明这个技能能做什么。
   技能附带的脚本属于外部代码，执行前要先看懂它在做什么。
